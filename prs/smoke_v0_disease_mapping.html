smoke_v0 disease mapping (D7): proposal for approval

Refs #430, #439 (decisions D6 and D7), #296, #244. Playbook: docs/mods_smoke_run_1_playbook.md §1.3, §3 (D6, D7) and §5.1 step 3.

Outcome (2026-09-29). This table was approved in PR #460 (2026-09-28), and backend/scripts/prs/build_smoke_v0_mapping_tsv.py now writes it. Gate F then released 590 of the 594 scores, over all 109 anchors, as smoke_v0 (release run c3be9df0). The four it held back were non-pick alternates that failed the post-D3 panel-coverage rule. Below is the proposal as it stood on 2026-09-28.

Nothing here is written to code or to the database. Choosing a disease anchor is an ontology mapping, so under the CLAUDE.md hard rule Richard approves the table before #430, #296 or #244 writes it. Every number below was measured on 2026-09-28 against the live quarantined E2 rows. They are re-measured on the E3 rows before release (§8). The document holds ids and counts only: no raw, z or percentile score values.

Summary

  • The #296 funnel reproduces exactly through R7 (3,752 → 1,861). R8, counted the way #296 counted it, gives 736 scores over 148 anchors, against #296’s 738 over 149. The whole gap is basal cell carcinoma (2 scores). It has no node in the composition under either spelling of its id (J10).
  • D7’s v0 exclusions then take the set to 594 scores over 109 diseases. They remove 24 multi-trait scores and 118 scores whose disease PrimeKG holds only inside a grouped node. The playbook’s “738 scores over 149 diseases” (D6, and the check in §5.1 step 3) is the count before D7. If this table is approved, that check should expect 594 / 109 on the E3 rows.
  • The CRC anchor is confirmed as MONDO:0005575 “Colorectal Cancer”. PrimeKG’s colorectal cancer node is merged into it under the padded CURIE, alongside CIViC and ClinVar. It has 7 drug neighbours: 5 through treats, 1 through contraindicated_for and 1 through has_off_label_use. The playbook’s “10 / 2 / 2” counts export lines, and every drug–disease pair is written in both directions. PrimeKG’s MONDO:24331 “colorectal carcinoma” has gene associations only (§5).
  • Of the 109 diseases, 94 are unambiguous and 15 are flagged, across nine judgement calls (J1–J9). J10 is an exclusion, so it has no row.
  • Two traps for whoever implements #430.
    • The scoring-file header maps all 9 v0 colorectal cancer scores to EFO_0005842. A mapping read from mods_prs_score_manifest.trait_efo would therefore lose the index disease.
    • The pickle reader settles ties in computed_at order. The chosen score for each disease therefore has to be written down explicitly (§8).

2. The rules applied

R1–R7, read from each row’s metadata:

  • R1: gate_c.weight_scale = 'additive'.
  • R2: gate_c.within_theoretical_bounds and gate_c.reconciles.
  • R3: gate_c.outcomes.scored ≥ 1.
  • R4: coverage_v1.structural_overlap, matched_rows / scoring_rows ≥ 0.90.
  • R5: gate_c.outcomes.ambiguous_palindromic = 0. These are the palindromic rows that reached orientation, the ones whose value depends on the pending palindrome decision.
  • R6: gate_c.n_complement_only_match / (scored + ref_allele_mismatch) ≤ 0.05, the same rate mods_prs_pipeline_service.strand_profile uses.
  • R7: coverage_v1.genotype_callability, callable_loci / matched_rows ≥ 0.90.

R8 and D7:

  • Trait source. The cached PGS REST metadata.json (trait_efo), cached 2026-07-09 to 2026-07-11. The REST value is the current mapping. The scoring-file header is what mods_prs_score_manifest.trait_efo holds, and it disagrees on 50 eligible scores. 36 of those are colorectal cancer, where the header still says EFO_0005842.
  • MONDO only. EFO, HP, OBA and PATO traits are not mapped.
  • Single trait. The REST trait list has exactly one entry. J9 covers how to read this rule.
  • Anchor. Take a node that carries the trait’s MONDO number under either spelling (MONDO:5148 or MONDO:0005148) and is in the composition:
    • if two such nodes exist, take the one that carries PrimeKG’s source (J1);
    • if there is no PrimeKG node, take the single CIViC/ClinVar/OncoKB node;
    • if only a MONDO_grouped: node carries the id, exclude it (D7);
    • if no node carries it, exclude it.
  • Vocabulary. maureen_focus_v1 as registered today: version v1, is_locked = false, last updated 2026-05-18 20:34 UTC. Its members are civic, clinvar, oncokb, pharmgkb_variants, and prime_kg minus the anatomy, cellular_component, molecular_function and exposure domains. The entity set is ModsKGCompositionService.build_filter’s SQL, verbatim. Relation counts follow materialize(): the relation comes from a member source, and both of its ends are in the set.
    • Cross-check: all 109 anchors appear in the de-facto foundation’s export on disk (916bdd2c, runs/2026-05-18_maureen_focus_v1/data/{train,valid,test}.txt).
    • The final check is against the new export’s vocabulary, after #432.
  • One score per disease. Take the most scored loci: snps_used, which equals Gate C’s outcomes.scored on every surviving row. This is today’s reader rule.
    • Tie-break: the lower PGS accession number.
    • J6–J8 propose overrides where the rule’s pick is wrong for her.

These are notes, not calls:

  • 27 anchors (62 v0 scores) have no drug neighbour in the composition (no drugs). The personalization adjustment is one hop (evaluate_personalized_maple.py), so their PRS cannot move any drug. The edge-type breakdown in M7 will show this.

  • 8 anchors are thin (thin): 5 or fewer in-composition relation ends. Check these first against the #432 export.

  • Umbrella classes have the most drug neighbours, and most of them are contraindications. Liver disorder has 644, every one through contraindicated_for. Hypertensive disorder has 403, and diabetes mellitus 381. The adjustment is edge-blind, so these push drugs the same way an indication would (#420). Worth knowing when reading M7.

  • Some diseases share the axis with their parent or child class. D7 keys by exact id and merges nothing, so a drug next to both nodes gets both adjustments. Examples:

    • urinary bladder cancer and urinary bladder carcinoma, which PrimeKG links to the same 12 drugs;
    • colorectal cancer and colorectal carcinoma (J3);
    • melanoma and cutaneous melanoma;
    • heart failure and congestive heart failure.

    That is acceptable for a machinery test.

  • MONDO:0005575 “Colorectal Cancer” (entity 257724). Its sources:

    • civic (civic_disease:9256);
    • clinvar;
    • prime_kg (PrimeKG node 28849, merged under the padded CURIE);
    • rtx_kg2.

    There is no MONDO:5575 entity.

  • Every drug edge on it is PrimeKG’s, and each is stored in both directions:

    • treats: fluorouracil, trifluridine, tipiracil, carmofur and cetuximab;
    • has_off_label_use: oxaliplatin;
    • contraindicated_for: indomethacin.

  • In the 916bdd2c export on disk, the node appears in 1,797 triples: 10 treats lines, 2 contraindicated_for and 2 has_off_label_use. These are the playbook’s numbers, and they count each drug–disease pair twice.

  • MONDO:24331 “colorectal carcinoma” (PrimeKG node 36480) has no drug edges. In the export it appears in 1,416 triples, all of them gene associations and subclass_of. MONDO:0024331 exists only in RTX-KG2.

  • The index position has 9 v0 scores. The chosen score is PGS003395, with 1,116,726 scored loci (J4).

  • The header trap: all 9 of those scores carry EFO_0005842 in the scoring-file header. Only the REST record gives MONDO_0005575.

8. For whoever implements #430, #296 and #244

These are notes, not decisions.

  1. Read traits from REST, or key by pgs_id from this table. Don’t read them from mods_prs_score_manifest.trait_efo, which holds the header. The header maps 36 colorectal cancer scores to EFO_0005842, including all 9 v0 ones.

  2. Write down the chosen score for each disease. resolve_prs_vector keeps the first row with the most snps_used while iterating in computed_at DESC order. That means:

    • the exact ties (J5–J7) would be settled by whichever row E3 happened to write last;
    • the reader would still take the AFR CKD score (J8).

    Either stamp disease_cui only on each disease’s chosen row, or give the reader the per-disease choice.

  3. The anchor is a CURIE, not a UMLS CUI, even though the column is named disease_cui. Carry it onto axis v2 verbatim. Don’t re-derive it with sorted(curies)[0] (#430).

  4. Re-run Appendix A.1 on the E3 rows once E3 has finished. The callset is the same and the policy is the default, so every count and every pick should reproduce exactly. If they don’t, stop (playbook §5.1 step 3). Don’t refresh the REST cache between now and the release, or else re-run this table.

  5. After #432, check all 109 anchors against the new export’s entity vocabulary. Start with the 8 thin ones.

  6. maureen_focus_v1 is unlocked. Lock it, or pin its member list in the #432 manifest, so that the vocabulary can’t drift underneath the mapping.

  7. A trap: PrimeKG’s mods_kg_entity_source.external_id is PrimeKG’s node index, not a MONDO number. external_id = '20804' is the drug Ioxilan (CHEBI:135884), not basal cell carcinoma.

Appendix A. The code behind every count

Every script is read-only. The container scripts open with SET TRANSACTION READ ONLY and select ids and counts, never raw_score, z_score or percentile. Run them like this:

A.1 smoke_v0_d7_repro.py: the funnel, R8, D7, the picks and the table
A.2 smoke_v0_catalog_checks.py: #430's numbers (1,620 / 245 / 42 / 173 / 50)
