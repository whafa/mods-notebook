Summary

We built the missing per-edge scoring pipeline so the v2 PDR2 foundation (maureen_focus_v1, 2026-05-18, A100-80GB, 21 hr) can be scored against Maureen’s RGCC drug-sensitivity panel under the same Tier-1 / Tier-2 framework that PDR1 was scored against in Phase 7.5. The pipeline is:

  1. backend/scripts/score_pdr2_edges.py build-edges — pulls Maureen’s RGCC sensitivities (112 distinct drugs from 224 agent_result rows, identical count to PDR1 Phase 7.5), resolves them to KG drug CURIEs via the v2 composition (mods_kg_entity drug-domain, with the same 30-entry alias map from compute_metrics_crc.py), and emits one edges CSV row per (drug CURIE × predicate). 110/112 drugs resolved (98%), 534 unique edges after collapsing duplicates (e.g., Doxorubicin

    • Liposomal Doxorubicin → same CHEBI).

  2. MODE=score_edges in the PDR2 container (new — see lib/pdr2/docker/entrypoint.sh

    • lib/pdr2/code/script/score_edges.py) — loads the foundation checkpoint via the same initialize_model() / entity_relation_dicts.pt path used by eval_patient.py (preserving the Maple entity_dict_forward vocab-key fallback), groups the input edges by (h, r), and does ONE forward pass per group — 3 forward passes total for our 3 predicates. Emits a scores.csv with raw model score, raw rank, filtered rank, and the train/valid/test split each edge falls in.

  3. backend/scripts/compute_metrics_rgcc_pdr2.py — joins scores ↔ RGCC ground truth, collapses multiple CURIEs per drug down to one row per drug (max raw_score across CURIEs), computes Tier 1 (Spearman ρ vs score_pct) and Tier 2 (AUROC, high-sens vs low+resistant) per-predicate and per-split-class. Headlines use MAPLE:sensitive_to_drug because that’s the predicate whose semantics align with “rank drugs by predicted sensitivity to Maureen’s tumor.”

A synthetic smoke test (where raw_score = score_pct/100 + N(0, 0.05)) correctly recovers Spearman ρ ≈ +0.91 and AUROC = 1.0, confirming the metrics + join layer wiring is correct end-to-end.

The real run landed on 2026-05-20. Cloud Build 5ac4f1e2-806a-4bd5-9ee7-7536f0f18d2a produced gcr.io/PROJECT/maple-pdr2-training:3fe1dc8-score-edges; Vertex customJob/1913996564225851392 waited ~5 min for A100 capacity and ran for ~4 min (69 s pure scoring across 3 (h, r) groups; the rest was dataset load). 447/534 input edges scored, 87 skipped (drugs whose CURIE wasn’t in the v2 foundation’s training vocab — primarily HMDB and a subset of pharmgkb_variants identifiers, see scores.csv status column).

1. Why a Custom Per-Edge Scorer Was Needed

eval_patient.py already exists and reports filtered MRR per predicate on Maureen’s outbound edges. So why couldn’t we use its output for Tier-1 / Tier-2?

Because eval_patient.json records per-predicate aggregates only (MRR, Hits@1/3/10, mean rank). It does not record the raw model score or the raw rank for any individual (h, r, t) triple, which is what Tier 1 / Tier 2 need:

  • Tier 1 (Spearman ρ between model score and RGCC % cell death): needs the model’s raw score for each drug, paired with RGCC’s continuous % cell death measurement for the same drug.
  • Tier 2 (AUROC, high-sens vs low+resistant): needs the same per-drug raw scores so we can rank them and compute the binary separation.

Per-predicate MRR collapses the per-edge information that the metrics require. So we need a scorer that emits scores at edge granularity.

This is exactly the missing piece called out in [[results/pdr2_track_a_v2_repro_writeup#6-open-questions-and-risks|PDR2 Track A v2 §6 open question 4]]:

“RGCC Tier-1 validation against v2 (Spearman ρ between predicted score and RGCC sensitivity class on Maureen’s 224 drug sensitivities) needs a custom (h, r, t)-scoring script — eval_patient.json records per-predicate aggregates but not per-edge raw scores. Tracked separately.”

This commit set ships that custom scorer.

Why score under all 3 predicates

We score each drug under all of MAPLE:sensitive_to_drug, MAPLE:partially_sensitive_to_drug, MAPLE:resistant_to_drug — not just sensitive_to_drug. The cost is free (3 forward passes vs 1 — the (h, r) batching makes per-tail scoring constant), and it lets us diagnose:

  • Does the model agree with the overlay’s predicate assignment for each drug? (Compare raw_score under each predicate to the natural_predicate we recorded at edge-build time.)
  • Does Spearman ρ hold under the inverse predicate too? (For MAPLE:resistant_to_drug, we expect ρ < 0 against RGCC % cell death — drugs the model says are “more resistant” should have lower % cell death.)
  • Are the per-predicate score distributions on the same scale, or does the model give systematically higher scores to one predicate?

Cross-predicate consistency is one of the cleanest tests of whether the model has learned semantics or just memorized labels.

Why the held-out split matters

Maureen’s overlay was built from RGCC sensitivities. The maureen_focus_v1 training data contains:

Predicateedges in trainedges in validedges in test
MAPLE:sensitive_to_drug512
MAPLE:partially_sensitive_to_drug≈ 45≈ 11≈ 11
MAPLE:resistant_to_drug≈ 40≈ 10≈ 10

(Exact counts from grep -c "MAPLE:.*_to_drug" runs/2026-05-18_maureen_focus_v1/data/{train,valid,test}.txt.)

So the model has trained on most of these labels. Tier 1 ρ computed over all-drugs is biased by training-set leakage — the model will appear to do better than it has learned to generalize. The honest measurement is Tier 1 ρ computed only on the held-out (valid+test) split. The metrics script reports both, so the reader can see the train-vs-held-out gap directly.

For drugs that are in RGCC but were NOT in the maureen_focus_v1 overlay (CURIEs the overlay materializer couldn’t resolve), the scorer flags split = "unknown" — these are pure generalization-from-graph-context tests.

4.3 Per-predicate breakdown (cross-predicate consistency check)

We scored each drug under all three predicates (~free under (h, r) batching). The question: does the model respect predicate semantics, or is it just scoring “this drug is relevant to Maureen”?

Predicatenρ vs RGCC %AUROC (high-sens vs low+resistant)overlay splits (train/valid/test/unknown)
MAPLE:sensitive_to_drug (headline)107+0.1810.8353 / 1 / 1 / 102
MAPLE:partially_sensitive_to_drug107+0.1580.70626 / 6 / 8 / 67
MAPLE:resistant_to_drug107−0.0060.67327 / 12 / 4 / 64

Read this table as the diagnostic for predicate semantics:

  • The sensitive_to_drug predicate yields the strongest positive ρ and highest AUROC, as semantics would predict. ✓
  • The resistant_to_drug predicate yields a near-zero ρ — exactly the “noise floor” we’d expect if the model had completely decorrelated the score from RGCC % under this predicate. We did not see ρ go negative (which is what would happen if the model also correctly learned the inverse semantics of “resistant”). Conclusion: the foundation has learned that sensitive_to_drug-relevant drugs are different from resistant_to_drug-relevant drugs, but the resistant predicate acts more as “drugs not related to me” than “drugs that affect me but negatively.”
  • AUROC > 0.5 under all three predicates (including resistant_to_drug at 0.67) confirms the model does score Maureen’s high-RGCC drugs higher than her low-RGCC drugs regardless of predicate — i.e., there’s a strong “is this drug Maureen-relevant?” component shared across all three predicates, on top of the predicate-specific signal.

The high-overlay-count predicates (partially and resistant) get worse Tier-1 ρ than the low-overlay-count predicate (sensitive_to_drug) despite having more training signal, which is another datapoint suggesting cross-predicate noise rather than per-predicate learning — the same architectural finding the v1 writeup made about λ=0.01 personalization saturating.

Split decision: PDR2 v2 wins Tier 2 by a solid margin (0.835 vs A1’s 0.751 — best PDR1; +0.084 absolute / +11% relative) and loses Tier 1 to PDR1 Run B by about half (+0.181 vs +0.351).

This split is consistent with the §4.3 finding that PDR2 v2’s strength is binary discrimination of extremes (high-sens vs resistant) and its weakness is fine-grained continuous ranking. Why this asymmetry might exist:

  • Architecture. PDR1 is CompGCN+ConvE; PDR2 is ULTRA+NBFNet. ULTRA was designed for inductive transfer across KGs — it learns relation types as a graph of meta-relations and embeds nodes via the labeling-trick. NBFNet’s iterative message passing tends to produce a few high-scoring tails per query and many low-scoring ones — a “spiky” score distribution. That’s exactly the pattern that helps AUROC (you can clearly separate the few high-scoring drugs from the bulk) and hurts Spearman ρ (the bulk has uninformative continuous order).
  • Carboplatin specifically. Removing Carboplatin from the matched set (n=106, RGCC high) recovers ρ to ≈ +0.26. The model places it at rank 260, which is wildly wrong even for a noisy ranker. Cisplatin and Oxaliplatin both rank in the top 4, so the model understands platinum-class CRC drugs in general; it’s missing something specific about Carboplatin’s KG embedding. Worth a dedicated dive — possibly an entity-alias issue in the overlay (Carboplatin in the v2 KG has different CURIE source coverage).
  • More raw signal, but on a sparser learning target. v2’s training data has 4.55M edges vs PrimeKG-only’s 8.1M. PDR2 v2 has more Maureen-specific information (variant-aware overlay, OncoKB LEVEL_1 edges) but less general drug-disease-gene density to ground its continuous score on. Less density typically hurts ρ-style metrics more than AUROC-style metrics.

The headline takeaway: PDR2 v2 succeeds where it matters most clinically (binary high-sens vs resistant discrimination) and lags PDR1 Run B on the more general continuous-ranking task. For a decision-support use case (which CRC drugs should we consider for Maureen?), AUROC = 0.835 is operationally far more useful than ρ = +0.351 with AUROC = 0.689; the model with the higher Tier 2 is better at surfacing the actual responders even when its Tier 1 is weaker.

4.5 Caveats inherited from PDR1 Phase 7.5

All of Phase 7.5 §5.4 applies verbatim here. Most pointed:

  • n_pos = 5 for Tier 2. The AUROC of 0.835 is computed against 5 high-sensitivity drugs. With this sample size the metric has high sampling variance; a single misclassified high-sens drug (Carboplatin at rank 260, in this run) significantly moves the number. The qualitative story (high-sens drugs cluster at the top of the model’s ranking) is robust; the exact AUROC is not.
  • In vitro CTC ≠ in vivo response. The model’s high-confidence picks include Cetuximab (RGCC low, 12.5%), Bevacizumab (RGCC low, 22.5%), and Ramucirumab — three first/second-line CRC biologics that don’t kill cells in a 48-h Annexin-V assay but are clinically central. The model is correctly surfacing them from KG context; the RGCC assay can’t credit them. Same observation as PDR1 Run B (Phase 7.5 §4.8).
  • No personalization in this score. This evaluates the baseline foundation. The fine-tune bundle (evaluate_personalized at λ=0.01) showed Δ_MRR ≈ -0.01% in v2 §4.5 so we wouldn’t expect personalization to materially change these numbers either — but a higher-λ sweep on the scoring side would be the natural follow-up.

5. Limitations and Caveats

  1. Training-set leakage on overlay drugs. The maureen_focus_v1 overlay materialized 135 sensitivity edges into the training set, built from the same RGCC data. Tier-1 ρ on those drugs is partly a memorization test. The metrics script reports valid+test as the honest held-out measurement. The 2 RGCC drugs that didn’t resolve (Catumaxumab, Everolimus/Temsirolimus combo cell) and any RGCC drugs that resolved to KG entities NOT in the overlay are pure generalization tests (split = "unknown").
  2. In vitro CTC ≠ in vivo response. Inherited from Phase 7.5 §5.4. RGCC measures Annexin-V+ at fixed concentrations in a 72-h (chemo) / 48-h (targeted) assay on Maureen’s CTCs. It does not measure pharmacokinetic exposure, drug-drug interactions, or metastatic-niche effects. Prodrugs (Capecitabine → 5-FU) typically underperform in vitro vs their active metabolite; the model can’t distinguish them mechanistically.
  3. Drug-name normalization is conservative. The 30-entry alias map from compute_metrics_crc.py was hand-curated for PrimeKG drug names. v2’s composition includes pharmgkb_variants and HMDB sources whose naming conventions are slightly different; we don’t yet have an exhaustive map for those edges. Two drugs (Catumaxumab, Everolimus/Temsirolimus combo cell) remain unmatched.
  4. Multi-CURIE-per-drug collapsing. v2’s KG carries many drugs under multiple CURIEs (Cisplatin: CHEBI:27899, HMDB:HMDB0014656, pharmgkb_variants:pharmgkb_drug:cisplatin). We collapse to the max raw_score across CURIEs at metrics time. The rationale: alias mismatch between sources shouldn’t penalize the drug. Downside: a poorly-connected CURIE never gets credit for being the “less informative” one, even if its low score is more honest. Inspect metrics.matched.csv if a high-sens drug looks anomalous; the n_curies column shows how many CURIEs were collapsed.
  5. Single patient. Same as Phase 7.5 §5.4. All findings pertain to Maureen specifically; cross-patient validation needs a cohort that does not currently exist in the Maple data.

8. Open Questions After This Run

  1. Carboplatin rank 260 outlier. RGCC high-sensitivity, 80.5% cell death, KG should know it as a platinum-class drug closely related to Cisplatin (rank 1) and Oxaliplatin (rank 2). Why does the v2 foundation place it at rank 260? Inspect the CURIE resolution: is the Carboplatin entity in mods_kg_entity poorly connected in the v2 composition relative to Cisplatin / Oxaliplatin? Removing Carboplatin from the n=107 set lifts Tier-1 ρ to ≈ +0.26 — meaningfully closer to PDR1 Run B’s +0.351. If this is a CURIE-coverage gap, it likely affects other drugs too and is a composition-quality improvement target.
  2. Why does partially_sensitive_to_drug underperform sensitive_to_drug despite having 5× the training overlay (33 overlay drugs vs 5)? Either the moderate-sensitivity edges in training are too noisy (RGCC moderate = 35-79% spans a wide range collapsed into one predicate), or cross-predicate noise is leaking signal from the better-trained predicate. The §4.3 cross-predicate consistency pattern is suggestive but doesn’t prove which.
  3. Predicate semantics under resistant_to_drug. The model correctly decorrelates score from RGCC % (ρ ≈ -0.006) under this predicate but does not invert the sign. A model that fully learned semantics should produce ρ < 0 — drugs the model says are most-resistant should have LOWER RGCC %, not random. Worth designing a targeted test for this (e.g., compare per-drug sensitive_to_drug score MINUS resistant_to_drug score against RGCC %; if semantics is learned, this difference should correlate much better than either score alone).
  4. The 87 skipped CURIEs. Drugs whose KG CURIE wasn’t in the foundation’s training vocab. Inspecting scores.csv status column shows the breakdown (mostly HMDB and some pharmgkb_variants). Either (a) the foundation should ingest these CURIE families in the next composition, or (b) the orchestrator should filter to the CURIE families known to be in-vocab before emitting the edge list. Trade-off: option (b) sacrifices coverage for clean reporting; option (a) needs another full training run.
  5. Personalization re-test. This evaluated baseline foundation only. Re-run with the fine-tune bundle (evaluate_personalized-style per-entity score adjustment) at higher λ values to see whether the criterion adjustment can lift Carboplatin specifically (the ATM criterion weight at +0.0249 in v2’s fine-tune signature should boost platinum-class drugs given Maureen’s ATM-low expression). The structural finding from v2 §4.5 says λ=0.01 is too small; the λ sweep results pending separately.
